Qué es SQL

01

SQL (Structured Query Language) es el idioma con el que se le habla a una base de datos relacional. No es un lenguaje de programación de propósito general: no tiene pantallas ni botones. Es un lenguaje declarativo, y esa es la idea que hay que interiorizar primero.

En un lenguaje imperativo uno dice cómo hacer algo: recorre esta lista, compara cada elemento, guarda los que cumplan. En SQL uno dice qué quiere, y el motor decide cómo conseguirlo:

Nadie le dijo al motor que abriera el archivo, que recorriera fila por fila ni en qué orden. Se le describió el resultado y él se las arregla.

Tres cosas que se confunden

NombreQué esEjemplos
SQL El lenguaje. Está normalizado por la ISO, así que lo básico funciona igual en todas partes. Un estándar, no un programa
El motor El programa que entiende SQL y guarda los datos en disco. Cada uno agrega su propio dialecto. MySQL, MariaDB, PostgreSQL, SQL Server, Oracle, SQLite
La base de datos El contenedor concreto donde viven tus tablas dentro de un motor. biblioteca, nomina, tienda
Sobre el dialecto Todo lo de esta guía está escrito en MySQL / MariaDB. Un SELECT se escribe igual en cualquier motor, pero detalles como AUTO_INCREMENT o LIMIT cambian de nombre entre uno y otro. Cuando algo sea propio de MySQL, aquí se dice.

Los sublenguajes

02

SQL no es una lista plana de instrucciones: está dividido en familias, según lo que cada instrucción toca. Saber a qué familia pertenece lo que estás escribiendo te dice de antemano qué tan peligroso es y si se puede deshacer.

DDL
Data Definition Language

Define la estructura: bases, tablas, columnas, llaves. No toca el contenido, dibuja el molde.

CREATEALTERDROPTRUNCATERENAME
DML
Data Manipulation Language

Mueve el contenido: mete filas, las cambia, las borra. La estructura queda intacta.

INSERTUPDATEDELETE
DQL
Data Query Language

Consulta sin modificar nada. Es una sola instrucción, y es la que más vas a escribir en tu vida.

SELECT
DCL
Data Control Language

Reparte permisos: quién puede consultar, quién puede borrar. Es del administrador, no del programador.

GRANTREVOKE
TCL
Transaction Control Language

Agrupa varios cambios en un todo o nada. Si algo falla a mitad de camino, se devuelve completo.

START TRANSACTIONCOMMITROLLBACK
La diferencia que cuesta caro El DML se puede deshacer dentro de una transacción con ROLLBACK. El DDL no: en MySQL, un DROP TABLE confirma la transacción sola y se lleva la tabla para siempre. Antes de escribir DROP, respira.

DDL: la estructura

03

Vamos a construir una biblioteca completa. El mismo ejemplo va a acompañar toda la guía: cuatro tablas, dos relaciones uno a muchos.

Crear la base y entrar en ella

CREATE DATABASE crea el contenedor; USE lo vuelve el actual. Son dos cosas distintas y hay que hacer las dos. El error más frecuente del primer día es crear la base y ponerse a crear tablas sin haber entrado en ella.

Los tipos de dato

Cada columna necesita un tipo. Elegirlo no es un trámite: es la primera regla de validación que va a tener tu base, y funciona incluso cuando el programador de la aplicación se distraiga.

TipoPara quéEjemplo de valor
INTNúmeros enteros: identificadores, cantidades, años1998
DECIMAL(10,2)Dinero y medidas exactas. Diez dígitos, dos de ellos decimales85000.50
VARCHAR(n)Texto de largo variable, hasta n caracteres. Ocupa lo que use'Gabriel García Márquez'
CHAR(n)Texto de largo fijo. Siempre ocupa n. Para códigos: país, sexo'CO'
TEXTTexto largo: una reseña, una descripción, un comentario'Novela publicada en...'
DATESolo fecha, en formato año-mes-día'2026-03-15'
DATETIMEFecha y hora'2026-03-15 14:30:00'
BOOLEANVerdadero o falso. En MySQL por dentro es un entero: 1 o 0TRUE
Un teléfono no es un número Un teléfono, una cédula o un código de barras se guardan en VARCHAR, no en INT. Nunca vas a sumar dos teléfonos, y en cambio sí necesitas conservar el cero de la izquierda y admitir signos como el +. La regla: es número solo si tiene sentido hacer cuentas con él.

Crear las tablas

Línea por línea:

  • id_autor INT AUTO_INCREMENT — el identificador. AUTO_INCREMENT hace que lo genere el motor: 1, 2, 3... Tú nunca lo escribes.
  • NOT NULL — esa columna es obligatoria; una fila sin nombre de autor no entra.
  • pais VARCHAR(40) — sin NOT NULL, así que admite quedar vacía.
  • PRIMARY KEY (id_autor) — declara cuál columna identifica la fila.

Ahora la tabla que depende de la anterior. La llave foránea es la línea que las conecta:

Dos formas de escribir lo mismo La llave primaria se puede declarar al lado de la columna (id_socio INT AUTO_INCREMENT PRIMARY KEY) o al final, en línea aparte (PRIMARY KEY (id_socio)). Las dos son válidas; la segunda es la única posible cuando la llave está formada por dos columnas. Elige una y sé consistente en todo el script.

Modificar y eliminar

MODIFY cambia el tipo dejando el nombre; CHANGE cambia el nombre y exige repetir el tipo. Es la confusión clásica del parcial.

InstrucciónQué borraFamilia¿Se deshace?
DELETE FROM libro; Las filas, una por una. Admite WHERE DML Sí, con ROLLBACK
TRUNCATE TABLE libro; Todas las filas de golpe. La tabla vacía queda ahí DDL No
DROP TABLE libro; La tabla entera: filas, columnas y definición DDL No

TRUNCATE además reinicia el contador de AUTO_INCREMENT y DELETE no. Si vacías una tabla con DELETE, el siguiente registro seguirá desde donde iba.

Restricciones

04

Una restricción es una regla que el motor hace cumplir siempre, sin que nadie tenga que acordarse de ella. Es lo que separa una base de datos de un montón de hojas de cálculo.

RestricciónQué garantiza
PRIMARY KEYIdentifica la fila. Es única y nunca nula. Una sola por tabla
FOREIGN KEYEl valor tiene que existir en la tabla a la que apunta
NOT NULLLa columna no puede quedar vacía
UNIQUEEl valor no se repite. A diferencia de la PK, admite un nulo
DEFAULTValor que se pone solo cuando no se da ninguno
CHECKCondición que todo valor debe cumplir
AUTO_INCREMENTEl motor genera el número. Propio de MySQL, y va sobre la llave

La llave foránea en acción

Esta es la restricción que más cuesta entender y la que más protege. Dice: este valor tiene que existir allá. Y el motor lo hace cumplir en los dos sentidos.

Se puede cambiar ese comportamiento al declarar la llave. ON DELETE CASCADE borra en cascada los hijos; ON DELETE SET NULL les deja la columna vacía. Úsalos con cuidado: CASCADE mal puesto borra media base sin preguntar.

DML: los datos

05

INSERT

  • Los textos y las fechas van entre comillas simples; los números, no.
  • La columna AUTO_INCREMENT no se nombra: el motor la llena.
  • Meter varias filas en un solo INSERT es mucho más rápido que hacer un INSERT por fila.
  • Si el texto lleva un apóstrofo, se duplica: 'O''Hara'.
Nombra siempre las columnas INSERT INTO autor VALUES ('Ana', 'Colombia'); funciona hoy y se rompe mañana, cuando alguien agregue una columna en la mitad de la tabla. Escribir INSERT INTO autor (nombre, pais) VALUES ... cuesta cinco segundos más y no se rompe nunca.

UPDATE

DELETE

El WHERE no es opcional UPDATE socio SET correo = NULL; borra el correo de todos los socios. DELETE FROM socio; vacía la tabla entera. Sin WHERE, la instrucción se aplica a todas las filas y el motor no pregunta.

La costumbre que te va a salvar: escribe primero el SELECT con ese mismo WHERE, mira cuántas filas salen, y solo entonces cámbialo por UPDATE o DELETE.

DQL: consultar

06

Una sola instrucción, SELECT, con muchas cláusulas opcionales que siempre van en el mismo orden. Esta es su anatomía completa:

Lo esencial

Los operadores del WHERE

OperadorQué haceEjemplo
= <>Igual, distintopais = 'Chile'
> < >= <=Comparacionesanio >= 1980
BETWEENRango, con los dos extremos incluidosanio BETWEEN 1960 AND 1970

NULL no es igual a nada, ni siquiera a NULL WHERE fecha_devolucion = NULL no devuelve nada, nunca, aunque haya filas vacías. NULL significa desconocido, y dos desconocidos no son iguales. Se pregunta con IS NULL y IS NOT NULL, y punto.

Funciones de agregado

Resumen muchas filas en un solo valor. Devuelven una fila, no una por registro.

COUNT(*) frente a COUNT(columna) COUNT(*) cuenta filas. COUNT(pais) cuenta valores no nulos de esa columna. Si tres autores no tienen país registrado, los dos números no coinciden, y esa diferencia suele ser exactamente lo que te están preguntando.

GROUP BY y HAVING

GROUP BY parte la tabla en montoncitos y aplica el agregado a cada uno. HAVING filtra esos montoncitos, igual que el WHERE filtra las filas.

WHERE o HAVING WHERE filtra filas antes de agrupar. HAVING filtra grupos después de agrupar. Por eso en el WHERE no puede aparecer un COUNT(): cuando el WHERE corre, todavía no existen los grupos.

JOIN: unir tablas

Normalizar reparte la información en varias tablas. JOIN es la instrucción que la vuelve a juntar para leerla, siguiendo la llave foránea.

La l y la a son alias: apodos cortos para no repetir el nombre completo de la tabla. Con dos tablas ya se agradecen; con cuatro son indispensables.

TipoQué devuelve
INNER JOINSolo las filas que casan en las dos tablas. Es el JOIN por defecto
LEFT JOINTodas las de la izquierda, casen o no. Las que no, salen con NULL
RIGHT JOINIgual, pero conservando la de la derecha
El LEFT JOIN sirve para encontrar lo que falta ¿Qué autores no tienen ningún libro cargado? Un INNER JOIN jamás te lo va a decir, porque descarta precisamente esas filas.

SELECT a.nombre FROM autor a LEFT JOIN libro l ON a.id_autor = l.id_autor WHERE l.id_libro IS NULL;

Orden de ejecución

07

Este es el concepto que separa a quien copia consultas de quien las entiende. El orden en que se escribe un SELECT no es el orden en que el motor lo ejecuta.

Se escribe así:

SE ESCRIBE 1.ºSELECTqué columnas quiero ver
2.ºFROM / JOINde dónde salen
3.ºWHEREqué filas me sirven
4.ºGROUP BYcómo las agrupo
5.ºHAVINGqué grupos me sirven
6.ºORDER BYen qué orden
7.ºLIMITcuántas filas

Pero el motor lo ejecuta en este otro orden:

SE EJECUTA 1.ºFROM / JOINarma la tabla de trabajo
2.ºWHEREbota filas
3.ºGROUP BYarma los grupos
4.ºHAVINGbota grupos
5.ºSELECTrecorta las columnas
6.ºORDER BYordena el resultado
7.ºLIMITcorta las primeras
Con esto se explican tres cosas de un solo golpe
  • Por qué el WHERE no puede usar un COUNT(): corre antes de que existan los grupos.
  • Por qué el WHERE no puede usar el alias que definiste en el SELECT: ese alias todavía no existe.
  • Por qué el ORDER BY sí puede usarlo: corre después del SELECT.

Trucos y trampas

08

Costumbres que valen la pena

  • Palabras clave en mayúsculas, tus nombres en minúsculas. Al motor le da igual, pero SELECT titulo FROM libro se lee de un vistazo y select TITULO from LIBRO no.
  • Una cláusula por línea. Cuando la consulta crezca a seis líneas vas a agradecer poder leerla en vertical.
  • snake_case para todo, sin tildes ni eñes ni espacios: fecha_prestamo, no Fecha Préstamo. Las tildes en los nombres de columna dan problemas de codificación tarde o temprano.
  • Tablas en singular. libro, no libros: cada fila es un libro. Lo importante es elegir una convención y no mezclarlas.
  • Comenta lo raro. -- comenta hasta el fin de la línea y /* comenta varias líneas */. Explica el porqué, no el qué.
  • Termina siempre en punto y coma. Es lo que separa una instrucción de la siguiente.

Las siete trampas de siempre

Se escribeQué pasaSe arregla

WHERE nombre = "Ana" Funciona en MySQL y falla en otros motores Comillas simples: 'Ana'

CREATE TABLE sin orden La FK apunta a una tabla que no existe Crear primero la tabla padre
telefono INT Se pierde el cero inicial telefono VARCHAR(20)
fecha = '15/03/2026' El motor no la reconoce Formato ISO: '2026-03-15'

Tres instrucciones para salir de dudas Cuando no recuerdes cómo llamaste algo, no adivines: SHOW DATABASES; lista las bases, SHOW TABLES; las tablas de la base actual, y DESCRIBE libro; te muestra las columnas de una tabla con su tipo, si admite nulos y cuál es la llave.

Ejercicios propuestos

09

Cambiamos de tema para que no se puedan copiar de los ejemplos. El caso es una veterinaria: atiende mascotas, cada mascota tiene un dueño y recibe consultas de un veterinario.

Trabaja en orden: el nivel 2 usa las tablas del nivel 1, y el 3 usa los datos del 2. Cada ejercicio tiene una pista que puedes abrir, pero úsala solo después de haberlo intentado.

Nivel 1 — DDL: armar la estructura

EJERCICIO 1Nivel 1

Crea la base de datos veterinaria y entra en ella. Después crea la tabla dueno con: identificador autogenerado, nombre obligatorio de hasta 80 caracteres, un teléfono y una dirección.

Ver pista
Son dos instrucciones antes de la tabla. Piensa bien el tipo del teléfono: ¿vas a hacer cuentas con él?
EJERCICIO 2Nivel 1

Crea la tabla mascota con identificador autogenerado, nombre obligatorio, especie, fecha de nacimiento y peso en kilos con dos decimales. Cada mascota pertenece a un dueño: agrega la llave foránea.

Ver pista
El peso es DECIMAL(5,2). La columna que apunta al dueño debe tener el mismo tipo que la llave primaria de dueno.
EJERCICIO 3Nivel 1

Crea veterinario (identificador, nombre, especialidad y una tarjeta profesional que no se pueda repetir) y consulta, que registra la fecha, el motivo, el diagnóstico, qué mascota se atendió y qué veterinario la atendió.

Ver pista
«Que no se pueda repetir» es UNIQUE. La tabla consulta lleva dos llaves foráneas, así que las dos tablas a las que apunta deben existir antes.
EJERCICIO 4Nivel 1

Te avisan que faltó registrar si la mascota está esterilizada, y que el motivo de la consulta se quedó corto en 60 caracteres. Arregla las dos tablas sin volver a crearlas.

Ver pista
ALTER TABLE ... ADD COLUMN ... y ALTER TABLE ... MODIFY COLUMN .... Para un sí o no, el tipo es BOOLEAN, y conviene darle un DEFAULT.

Nivel 2 — DML: llenar y corregir

EJERCICIO 5Nivel 2

Inserta cuatro dueños, seis mascotas (al menos un dueño con dos), tres veterinarios y ocho consultas repartidas entre 2025 y 2026. Todo con el menor número posible de instrucciones INSERT.

Ver pista
Son cuatro INSERT, uno por tabla, cada uno con varios grupos de VALUES separados por comas. Y en orden: primero los dueños, porque las mascotas apuntan a ellos.
EJERCICIO 6Nivel 2

Una mascota subió de peso: actualiza el suyo a 12.40 kg. Otra cambió de dueño: pásala al dueño número 2. Hazlo en dos instrucciones y asegúrate de que cada una toque exactamente una fila.

Ver pista
Filtra por la llave primaria, que es lo único que garantiza una sola fila. Antes de ejecutar el UPDATE, corre el mismo WHERE con un SELECT.
EJERCICIO 7Nivel 2

Intenta borrar un dueño que tenga mascotas registradas. Copia el mensaje de error que te devuelve el motor y explica con tus palabras qué te está diciendo. Después haz lo necesario para poder borrarlo de verdad.

Ver pista
No es un error tuyo: es la llave foránea haciendo su trabajo. Para borrarlo hay que ocuparse primero de las filas que lo referencian — y si esas mascotas tienen consultas, de las consultas antes que nada.
EJERCICIO 8Nivel 2

Borra todas las consultas anteriores al 1.º de enero de 2026. Antes de ejecutarlo, escribe la consulta que te dice cuántas filas se van a ir.

Ver pista
Primero SELECT COUNT(*) FROM consulta WHERE ... y después el DELETE con ese mismo WHERE. Las fechas van entre comillas y en formato 'AAAA-MM-DD'.

Nivel 3 — DQL: preguntarle a la base

EJERCICIO 9Nivel 3

Resuelve cada una con una sola consulta:

  1. Todas las mascotas ordenadas de la más pesada a la más liviana.
  2. Las mascotas cuyo nombre empiece por la letra M.
  3. Las mascotas que pesen entre 5 y 15 kilos.
  4. Las mascotas a las que no se les registró la fecha de nacimiento.
  5. Las tres consultas más recientes.
Ver pista
En orden: ORDER BY ... DESC, LIKE 'M%', BETWEEN 5 AND 15, IS NULL, y ORDER BY ... DESC LIMIT 3.
EJERCICIO 10Nivel 3

Cuántas mascotas hay en total, cuál es el peso promedio por especie, y qué especies tienen más de una mascota registrada.

Ver pista
Tres consultas. La segunda es GROUP BY especie con AVG(peso); la tercera agrega HAVING COUNT(*) > 1. Recuerda que la condición sobre el conteo no puede ir en el WHERE.
EJERCICIO 11Nivel 3

Un listado con el nombre de la mascota, el nombre de su dueño, la fecha de la consulta y el nombre del veterinario que la atendió, ordenado por fecha.

Ver pista
Son tres JOIN encadenados partiendo de consulta. Usa alias de una letra y, como hay dos columnas llamadas nombre en tablas distintas, ponles alias también a ellas con AS.
EJERCICIO 12Nivel 3

Qué mascotas nunca han tenido una consulta. Piensa bien qué tipo de JOIN necesitas: el normal no sirve.

Ver pista
LEFT JOIN desde mascota hacia consulta, y luego te quedas con las filas donde el lado de la derecha quedó vacío: WHERE c.id_consulta IS NULL.
